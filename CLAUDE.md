# CLAUDE.md

Guidance for Claude (and people) picking up this repo. Read `README.md` for what the prototype does. This file covers how we work on it and why things are the way they are.

## The project

An interactive map of Horizon Power's 117 remote Aboriginal communities in WA, built by VML for Horizon Power (HP) Remote Communities. The client brief (22 Sep 2026) asks for community profiles, works by program (ReGen, AMI, CDNP), community engagement and five flagship stories.

**Current phase:** a simple, clickable wireframe prototype for client review, in plain HTML, CSS and vanilla JavaScript in `prototype/`. The larger React, MapLibre and custom CMS build in `plan.md` is **parked**. Don't start on it unless asked.

### Version 2 changes (client feedback, running log)

Everything below applies to `prototype-v2/` only; v1 is untouched. Add each change here as it's made.

- **Map markers (25 Nov 2026):** the unselected community is a simple dot again, not a pin: 14px, Mid 1 `#D44A31` with a white ring (`images/design/map-dot.svg`, made in the same shape as the blue `map-dot-faded.svg`; it isn't a Figma export). The red pin is now only the selected state (the larger outlined pin, unchanged). Story communities are dots too until selected, so a story is no longer marked on the map (groups containing one still have their red ring; ask the client if that distinction should come back). The Key now reads Community (dot), Selected community (pin), Not in current filter, Group of communities; its "Community with a story" row is gone. "Not in current filter" is still the blue dot. The pin art `map-pin.svg` and `key-pin.svg` are no longer used in v2.
- **Sentence case and earlier place names (25 Nov 2026):** the map's region names are no longer all caps; they show as typed (Kimberley, Pilbara, Gascoyne/Mid West, Esperance/Goldfields). That was the only all-caps text (acronyms such as AMI and CDNP stay as they are). Community names now start showing at 1.4 × the whole-of-WA view (`LABEL_ZOOM` in `app.js`; version 1 used 3.5), which is two zoom-button presses (1.6 × each) earlier: after one press of + about 27 names show at 1440 × 900, and all 117 still show at full zoom. Names still only take a free spot, so crowded areas fill in as you zoom.
- **Region labels (25 Nov 2026):** the map's region names are 16px (the same as the community names) in Desert/Dark `#780D02` (`.region-label` in `styles.css`; they were 10px navy). The weight stays semibold with 4% letter spacing and the 1px white outline. **They dodge things automatically** (`renderRegionLabels()` in `app.js`, drawn after the markers and community names each render): each name takes the spot nearest its designed position (`RC_REGION_LABELS`) that overlaps no group, dot, community name, Key or zoom button, keeps its whole name inside the map and stays on its own region's land (a point-in-polygon test on the region shape plus the coastline via `Path2D`). Community names are placed first, so a region name never displaces one. Spots are tried nearest first within 140 × 100px and the search stops early, so it costs almost nothing per frame.
- **Smooth zoom (25 Nov 2026):** the wheel and the +/- buttons ease instead of jumping (`zoomSmooth()` in `app.js`). Each press or wheel notch moves a zoom goal and the view eases toward it (an exponential ease with an 85ms time constant, about a quarter of a second to settle, in log space as zoom is multiplicative), keeping the point under the cursor, or the map's centre for the buttons, fixed. Goals add up, so quick repeats glide on without restarting; a glide (cluster click, opening a profile) cancels it; reduced-motion users still jump. Pinching on a touch screen still tracks the fingers directly. Version 1's buttons jumped a full 1.6 × in one frame; the biggest step per frame is now about 1.07 ×. **Names hold still while the zoom changes (client edit):** `applyView()` only slides the existing markers, names and region names with the map (`slideMarkers()`; each carries its map position in `data-ux`/`data-uy` and a fixed screen offset in `data-dy`, or `data-ox`/`data-oy` for region names) while the zoom level is changing, and redoes the groups and name spots once it has been still for 120ms. Before this, every frame re-placed the names and they jumped between spots (11 to 13 changes per zoom press; now one, when it settles). Panning at a steady zoom still redraws every frame. The cost is that new names and groups appear when the zoom stops, not during it.
- **Details under the name (25 Nov 2026):** in both profiles the key details (Region and Service provider on a simple profile; Population, Languages spoken, Traditional Owners and Service provider on a story profile) now sit in the space under the place name (and its "Also known as" line), above the torn sand band, in the same two-column grid with 16px above it (`factsBlock()` inside `.profile-name`, `.profile-name .facts` in `styles.css`). The sand band (`aboutBlock()`) now holds only the works, and is labelled "Works in [name]" for screen readers. The details line up with the name (32px sides, 16px on phones); the works keep the band's own 57px sides.
- **High content (story) nodes (25 Nov 2026):** a community with a story is a larger bush green dot, 22px: a `#4C6A48` centre (the colour is the client's; it's not in the creative's palette notes), a 2px white ring and a 2px green ring outside it (client edit). Dot, group and selected pin all use the same 2px white and 2px green rings, against the 14px Mid 1 dots (`images/design/map-dot-story.svg`, made in the same shape as the other dots, not a Figma export). When selected it becomes the larger outlined pin recoloured bush green (`images/design/map-pin-large-green.svg`, redrawn from the creative's teardrop as bush green inside a 2px white ring inside a 2px green ring; the creative's inner outline band is gone; not a Figma export), and its highlighted name and tooltip (hover, focus, selected) are bush green too (`.marker.is-story` in `styles.css`; `--bush` token). Other communities keep the red pin and the dark red highlight (client edit: the green is for high content nodes only). Outside the filter it's the blue dot. Its name sits a little further out (18px from the centre, `.marker.dot-story` in `styles.css` and `placeLabel()` in `app.js`) and it reserves a slightly larger space for names. The Key has its "Community with a story" row back, with a green dot; its "Selected community" row still shows the red pin. A group containing a story is bush green too (disc and 2px outer ring, client edit); other groups stay red. This replaces the note above that stories were just dots until selected.

## Working rules

- **Commit titles say what changed, in 50 characters or fewer,** e.g. "Remove All communities link from profiles". The GitHub Actions list truncates longer titles, which looks untidy; put detail in the commit body. Don't start every title with the same prefix: they become impossible to tell apart in the history.
- **Commit and push straight to `main`.** No feature branches or PRs unless asked. Every push to `main` updates the live site: https://hugo-j-vml.github.io/hp-rc-map/ (GitHub Pages, deployed by `.github/workflows/pages.yml`, so each run in the Actions tab is titled with its commit message. The root `index.html` is the launch page).
- **UK English and Australian dollars** in all copy and docs.
- **Say "the creative"** for the designer behind the visual treatment, in chat, docs, comments and commits. Never "she", "he" or "they" for them, and don't guess anyone's pronouns.
- **Keep it simple:** no frameworks, build step, package manager or external JavaScript libraries. It must still work when `prototype/index.html` is opened straight from disk (`file://`), so data is loaded as `<script>` files, not `fetch`.
- **Brand font, never committed:** Horizon Power's font is Beausite Classic (Fatype), licensed for internal HP use only. The `.woff2` files go in `prototype/fonts/`, which git ignores, so they never reach the public repo or Pages site; there everything falls back to Inter. Without the files the browser logs four "file not found" errors for them; that's expected. Never commit font files, and never link to HP's own font files on their website.
- **Wireframe fidelity:** greyscale, using the grey tokens at the top of `styles.css` (they match the Figma "Wireframe kit v2 (HP design system lookalikes)"), **except where the creative's visual treatment has been rolled in**. It's arriving piece by piece; so far the profile panels, the header logo, the map, the landing heading colour, the landing story band and the landing and filters buttons (see "Visual treatment" and "Buttons" below). The rest of the landing panel, filters and header are still the wireframe. When rolling in more of it: **no interpretation**. Copy values from the creative's Figma, and ask the user about anything the design doesn't settle.
- **Match the surrounding code:** ES5-style JavaScript (`var`, `function`, no arrow functions), one IIFE in `app.js` split into `// ---------- Section ----------` blocks, short "why" comments.
- **Plain-language, culturally safe copy:** say "Aboriginal" (not "Indigenous"), "power" (not "energy"/"electricity"), "Yarn with us", and spell out acronyms. Placeholder copy goes in `[square brackets]`, as in Figma.
- **Check your work before pushing.** Chromium and Playwright are available in cloud sessions (`require('playwright')`). Screenshot at 1920×1080, 1440×900 and 390×844 (mobile), check for console errors, and look at the screenshots. Keep test scripts and screenshots in the session scratchpad, **never in the repo**.

## Decisions and why

- **Regions.** Use HP's four service areas: Kimberley, Pilbara, Gascoyne/Mid West, Esperance/Goldfields. The South West Interconnected System area stays blank.
  - Each community's region comes from HP's **district code** (spreadsheet column K: WKIM/EKIM → Kimberley, WPIL/EPIL → Pilbara, GS-NOMW/COMW → Gascoyne/Mid West, CEMW → Esperance/Goldfields), not from where it sits on the drawing. Counts: 78 / 17 / 8 / 14.
  - The poster's boundaries agree with the district codes for 105 of the 117 communities. The 11 Ngaanyatjarra (NG) lands communities sit in the poster's Gascoyne/Mid West band but are coded Esperance/Goldfields (serviced from Esperance), and Kurrawang sits in the blank SWIS notch near Kalgoorlie. The "Goldfields takes in the NG lands" option shows the alternative drawing (see open questions).
- **Names.** "Blackstone" is shown as **Papulankutja** (also known as Blackstone), per the brief and Figma. Parenthetical and contract-name variants become "also known as" names and are searchable.
- **Map.** Plain SVG with an equirectangular projection calibrated to the Figma outline (see `outline.js`). There is no basemap or tile service.
  - Max zoom is 80× the state view, so the closest pair (Embulgun/Munget, about 700 m apart) separate. At full zoom there is no clustering.
  - Zoomed-in artefacts on the simplified coastline are accepted for the prototype.
- **Labels.** Each name takes the first free spot around its dot: right, left, top, bottom, then the corners. Other dots and names count as obstacles.
  - Hover, focus and selection highlight the name **in place**. The floating tooltip only shows for dots without a visible name.
  - Names are part of their dot's button, so clicking or tapping a name selects the community just like its dot. A drag that starts on a name still pans the map.
  - Names are nudged 2px down to sit optically centred.
- **Map visual treatment (Nov 2026):** from the creative's D01 and overview frames. Sea `#E3EBF7`; the SWIS area `#FBFBFA`; service areas Kimberley `#EAE7E2`, Pilbara and Esperance/Goldfields `#F2F0EC`, Gascoyne/Mid West `#F7F6F4`, each outlined 2px `#D9D3CA`. The design's "smooth edges" are 4px rounded corners on the service areas at the whole-of-WA view: `roundedPath()` in `app.js` rounds every corner by 4.8 units (the design draws our outline at 0.832 scale), so the ngLands option's shapes get the same treatment. The land and coastline are the creative's own smoothed shape (`RC_COAST` in `outline.js`): the design's coastline vector has corner radii on its points (mostly 4px, some 1 or 2px), which a plain point export loses, so the shape is copied from Figma's SVG export with the rounding built in and placed on our outline space by a transform. Its points differ slightly from our raw outline (it was re-simplified), but communities sit on it to within half a pixel at the whole-of-WA view. The coastline is navy, 1.5px on the inside of the edge (a 3px stroke clipped to the land). The design has a second, 1px coastline vector; it's left out because it's slightly offset and doubles the line once you zoom in. Region names are 10px semibold navy with 4% letter spacing and a 1px white outline, placed where the design has them (tried at 16px and put back: too big for the map).
  - **Markers:** a single community is a red pin (the creative's artwork, scaled up 30% by the client's request: 26px, and the larger story pin 23.4 × 32.5px) with its tip on the spot; story communities and the selected community use the larger outlined pin. Communities outside the current filter are blue `#6E87B4` dots, groups outside it are blue too. (The design's D01 shows blue dots for ordinary communities, but that's indicative only; the user confirmed blue is just for "not in current filter".) Groups are a 36px red `#780D02` disc (32px inside a 2px white border; client edit, they were 40px with 3px) with an Inter Bold 14 count; a group containing a story gets a 2px red outer ring. Names are Beausite Medium 16px navy (client edit; 13px in the design) with a 1px white outline; hover, focus and the selected community show the name on a red label (Inter Semibold 16px, white). The numbers in groups stay at 14px. The selected community keeps its large pin even when it's outside the filter.
  - **Key:** white, 1px navy border, 236px wide, Inter (as in the design); its pins are the creative's artwork.
- **Header:** the creative's logo lock-up (Horizon Power, a divider, Remote Communities; exact files and desktop sizes from Figma, scaled to 24px tall on mobile, the user's choice as there's no mobile design). Otherwise a greyscale wireframe of the live HP Remote Communities site header (logo; Contact us, Login, Search; Program purpose, Community progress, Latest news, Community members). Header Search focuses the map search; the other links show a "not part of the prototype" notice.
- **Sidebar:** 560px for every view on desktop, so it never jumps width.
- **Landing heading and buttons (Nov 2026):** "Power for remote communities" uses the profile name's colour (`--red`, `#780D02`). The landing and filters panel buttons follow HP's Design System buttons: primary ("Show N communities") is Core/Orange `#C54630` with white text; secondary (Filters) is a 2px outline with text and count badge in Core/Navy `#001E3C` (client edit, it was orange; it now goes with the navy search field). Both darken to Desert/Dark `#780D02` on hover (the secondary hover follows the design system's theme buttons, as the core one has none). Filters has a sliders icon and shows a count of active filters. Search results drop down **over** the content below, like a native select, rather than pushing the story list down as you type (client edit). They close on Escape or a click or tab outside the field, and reopen on typing or clicking back in. On mobile, typing opens the sheet to full height so the list fits.
- **Key:** shows on load, then collapses to a "Key" pill on first map interaction. The collapsed Key is a 36px-tall button (square 4px corners, styled exactly like the zoom buttons: white fill, 1px grey border, dark text and chevron; the chevron points up when collapsed, as the key opens upwards, and down when open, client edit) to match the zoom buttons (client edit, an experiment). On mobile it starts as the pill.
- **Mobile map controls:** the key pill and zoom buttons sit bottom right (the zoom buttons are 36 × 36px with 20px icons, client edit), just above the bottom sheet, and move up with the sheet when a profile opens (the sheet heights, 40% and 71%, are shared between `styles.css` and `visibleArea()` in `app.js`).
- **Sidebar story cards are whole-card links, with no "Read more":** "Read more" links aren't accessible (they all read the same out of context). Each card's title is its one link, named after the community, stretched over the card with `::after`. Hover underlines the title; keyboard focus outlines the whole card. Use the same pattern for any new cards.
- **Profiles have no tabs (client edit, Nov 2026):** the content scrolls down the panel in one column. There are no "Community story" or "Our team visited" tags under the name (client edit). There is no "Last updated" line or footer "Yarn with us" link at the bottom (client edit); the nearby communities close the profile, with 32px of padding above them at every breakpoint. In-panel links can use `data-jump` (none do now) to scroll the panel without changing the route hash.
- **Hear the name:** a speaker button after the community name in both profiles (`nameRow()` in `app.js`), labelled "Hear how to say [name]". It will play a recording of a community member saying the name, with permission. Never use text-to-speech, which gets Aboriginal names wrong. There are no recordings yet, so it shows a placeholder message.
- **Closing a profile:** the cross (and Escape) close the profile and glide the map back to the opening whole-of-WA view, on every screen size (`closeProfile()` → `fitState(true)`). ## Prototype options panel (Shift + O)

Layout experiments the user can switch on and off to compare. They are stored in `localStorage` (`rcm-prototype-options`) and can be overridden by URL parameters (e.g. `?ngLands=1`).

To add an option:
1. Add an entry to the `OPTIONS` array in `app.js`: `{ id, label, description, initial, requires? }`. `requires` greys it out until another option is on.
2. Read `options.<id>` where it matters.
3. React to changes in `applyOptions()`.
4. Document it in the README.

Current options: `ngLands` (NG lands region drawing). Floating story cards, pinned cards and progress bars were removed after client review (Nov 2026); they're in the git history if needed again.

## Environment gotchas (cloud sessions)
